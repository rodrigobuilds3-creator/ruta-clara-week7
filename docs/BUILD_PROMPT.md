# Implementation prompt — Ruta Clara, Week 7

Use `docs/PACKET.md` as the product-scope source. Build an accessible, responsive static academic demo, not a real reporting service. Use invented cases and illustrative Atizapán coordinates; do not imply a validated route, worker-controlled data governance, independent review, institutional repair, payment, or safety outcome. The demo does not request personal identifiers, but its free-text field cannot technically prevent someone from entering them. All case data remains temporarily in the current browser tab's memory and is not submitted to a server.

Implement in small, testable increments:

1. **Report screen and map.** Use an interactive SVG map. Keyboard and pointer users can choose an illustrative point; display the chosen coordinates; never request geolocation automatically.
2. **Validated report form.** Require a category, 12–240 character description, and illustrative point. Show announced inline errors; support correction; insert user text as text, never unsafe HTML.
3. **Synthetic model.** A small deterministic k-nearest-neighbors model may use invented labeled examples and return a review suggestion only. Explain that it is not field validated and cannot verify a hazard, determine payment eligibility, sanction, or close a case.
4. **Optional motion-sensor demonstration.** On compatible phones, ask for permission only after explicit user action and read motion for three seconds. Discard raw events after calculating the peak; do not use GPS or continuous tracking. A simulated-sample fallback is available. Explain the derived value's temporary tab-memory lifetime and that the feature is only for demonstrating a possible review signal, not proving a hazard.
5. **Local workflow state.** The same anonymous demo user operates the simulated reporter, verifier, and case-owner controls. Support submit, reject, correction/resubmission, simulated verification, and simulated closure with a reason. Verification may set only “Elegibilidad hipotética (demo)”; no payer, amount, or transfer exists. Every case except `closed` remains in the unresolved count.
6. **Limitations and history.** Show that cases are invented, roles are simulated, nothing is sent to an authority, and the report exists only in this tab. Present worker protections, compensation, purpose limits, access, retention, and deletion as requirements for a future pilot—not controls delivered by this build.

Use built-in Node tests for pure logic, build/package checks, and browser smoke tests. For the isolated project history, the planned sequence was: (1) packet/scaffold, (2) map/form, (3) model/sensor, (4) ledger/limitations, (5) tests/review. Record only actual commits, deployments, and test results. Never fabricate user research, team approval, official partners, successful repairs, or a video. Keep `DECISIONS.md` current and separate observed facts from assumptions.
